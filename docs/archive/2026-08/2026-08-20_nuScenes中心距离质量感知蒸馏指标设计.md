# nuScenes 中心距离价值感知蒸馏 Baseline 设计

日期：2026-08-20  
更新：2026-08-21  
状态：Baseline 设计已确定，尚未实现  
适用范围：LabelDistill 的 teacher proposal–GT 匹配、BEV ROI 价值估计与 feature distillation loss

## 1. 核心问题

当前 LabelDistill 使用冻结的 LiDAR CenterPoint teacher 产生 proposal，将 proposal 与 GT 匹配，根据匹配结果生成 BEV Gaussian mask，再约束 camera student 与 LiDAR teacher 的两级 BEV 特征。

传统 GT-guided mask 只回答：

```text
在哪里蒸馏？
```

但 GT 位于某个区域，并不意味着 teacher 在该区域一定学到了同等可靠的 BEV 表征。冻结 teacher 的检测头可以作为 teacher BEV 的任务探针：如果它能从某个 GT 附近解码出类别正确且中心接近的 prediction，说明该实例对应的 teacher BEV 具有更高的可迁移价值；中心偏差越接近可信边界，teacher 对该实例的定位能力越弱。

本 baseline 因而回答第二个问题：

```text
当前 GT 所覆盖的 teacher BEV 值得蒸馏多少？
```

核心原则是：

> GT 定义蒸馏的空间载体，teacher prediction 与 GT 的中心距离估计该实例的 teacher value，实例级 loss 聚合保证该 value 真正控制知识传递强度。

## 2. Baseline 一句话定义

当前确定的 baseline 为：

```text
exact-class-only
+ small 1m / large 2m class-group trust radius
+ score-first nearest-unmatched one-to-one matching
+ continuous center-distance teacher value
+ per-GT fixed-count feature loss reduction
```

不再采用：

- same-task-group fallback；
- High / Medium / Unmatched 离散质量档；
- 2～4m 的弱匹配；
- small / large 两套人工分段权重表；
- union-max mask 后再除以 `mask.sum()`；
- unmatched GT 的正向 teacher feature prior。

## 3. nuScenes 指标依据

nuScenes detection AP 使用地面平面内的 2D 中心距离匹配，不使用 IoU 作为 TP 判定条件。

四个 AP 匹配距离为：

```text
0.5m, 1.0m, 2.0m, 4.0m
```

TP metrics（mATE、mASE、mAOE、mAVE、mAAE）统一在 2m 中心距离下完成匹配。官方匹配严格使用 `distance < threshold`，并要求类别一致和 one-to-one。

需要区分两件事：

1. nuScenes 官方对所有类别使用统一 TP 匹配阈值；
2. 本方法不是重新定义官方 TP，而是用官方中心距离作为 teacher competence 的观测量，并根据实例空间敏感性定义蒸馏可信半径。

因此本文应表述为：

> We adopt the nuScenes center-distance criterion to measure teacher localization competence and use scale-conditioned trust radii for knowledge transfer.

不能表述为“nuScenes 对 small 使用 1m、对 large 使用 2m”。

## 4. 类别分组与可信半径

### 4.1 Small / strict group

```text
barrier
motorcycle
bicycle
pedestrian
traffic_cone
```

可信半径：

```text
tau_small = 1.0m
```

small object 的局部空间支持较紧凑，同样的绝对中心偏差会跨越更大的相对目标尺度。当前基础 BEV 输出步长约为 0.8m，1m 偏差已接近或超过一个基础 BEV cell。

barrier 虽可能很长，但横向较窄，第一版仍放入 strict group；后续单独报告其结果，并评估是否需要 elongated group。

### 4.2 Large / tolerant group

```text
car
truck
construction_vehicle
bus
trailer
```

可信半径：

```text
tau_large = 2.0m
```

large object 在 1～2m 中心偏差下仍可能保留有效的 BEV 空间覆盖，因此使用 nuScenes TP metrics 的 2m 上界。

### 4.3 统计依据

CenterPoint step 50200 的最近 exact-class proposal 覆盖率为：

| split | small `<1m` | small `<2m` | 1→2m 增益 | large `<1m` | large `<2m` | 1→2m 增益 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| train | 97.92% | 98.54% | 0.62% | 92.18% | 95.57% | 3.39% |
| val | 97.59% | 98.26% | 0.67% | 91.71% | 95.13% | 3.42% |

R50 teacher train 统计呈现相同趋势：

```text
small 1→2m 增益：0.98%
large 1→2m 增益：4.64%
```

因此 small 放宽到 2m 的额外覆盖不足 1%，而 large 会获得稳定的 3.4～4.6% 额外覆盖。该规律跨 teacher、跨 train/val 一致，支持 small 1m / large 2m。

## 5. 候选关系与 one-to-one 匹配

### 5.1 候选边

对 prediction `p_j` 和 GT `g_i`，只有满足以下条件才建立候选边：

```text
prediction 与 GT 精确同类
GT 位于对应类别的官方评测范围内
BEV 中心距离 d_ij < tau_i
```

形式化为：

```text
(p_j, g_i) in E
iff class(p_j) == class(g_i) and d_ij < tau_i
```

距离边界严格使用 `<`，不使用 `<=`。

### 5.2 Official-style greedy assignment

对每个类别独立执行：

```text
1. teacher predictions 按 score 从高到低排序；
2. 依次处理 prediction；
3. 在该 prediction 的 exact-class、尚未匹配 GT 中寻找中心距离最近者；
4. 若距离严格小于该类别可信半径，则建立匹配；
5. prediction 和 GT 均标记为已占用；
6. 否则该 prediction 不参与正向 ROI feature distillation。
```

score、distance 和 value 的职责分离：

- teacher score 只决定 prediction 的处理优先级；
- center distance 决定 prediction 匹配哪个尚未占用 GT；
- 匹配完成后的 center distance 决定 teacher value；
- baseline 不将 raw teacher score 乘入 value。

### 5.3 四种匹配情况

| 情况 | Baseline 处理 |
| --- | --- |
| GT 没有候选 prediction | unmatched，teacher value 为 0 |
| GT 只有一个候选 prediction | prediction 未被占用时正常匹配 |
| GT 有多个候选 predictions | score 更高的 prediction 优先参与全局 assignment；GT 最终最多匹配一个 prediction |
| 一个 prediction 靠近多个 GT | 只匹配最近的尚未占用 GT；其他 GT 继续寻找候选或变为 unmatched |

当前旧 matcher 是 GT-centric 独立选择，虽然每个 GT 最终只保存一个 prediction，但同一个 prediction 可以被多个 GT 重复使用。one-to-one 的目的不是单纯模仿 evaluator，而是避免将同一份 teacher response 复制成多个 GT 的可靠知识。

## 6. 连续 Teacher Value

匹配完成后，设实例 `i` 的中心距离为 `d_i`，对应类别组可信半径为 `tau_i`：

```text
r_i = d_i / tau_i
```

baseline 使用无额外可调参数的 normalized squared margin：

```text
q_i = max(0, 1 - r_i^2)
    = max(0, 1 - (d_i / tau_i)^2)
```

未匹配实例定义：

```text
q_i = 0
```

归一化距离与价值关系：

| `d / tau` | `q` |
| ---: | ---: |
| 0.00 | 1.000 |
| 0.25 | 0.938 |
| 0.50 | 0.750 |
| 0.75 | 0.438 |
| 1.00 | 0.000 |

映射到实际距离：

| small distance | small value | large distance | large value |
| ---: | ---: | ---: | ---: |
| 0.00m | 1.000 | 0.00m | 1.000 |
| 0.25m | 0.938 | 0.50m | 0.938 |
| 0.50m | 0.750 | 1.00m | 0.750 |
| 0.75m | 0.438 | 1.50m | 0.438 |
| `>=1.00m` | 0.000 | `>=2.00m` | 0.000 |

采用 `1-r^2` 而不是人工分档的原因：

- value 随中心距离连续变化；
- 在零误差附近斜率为零，不会过度惩罚微小定位抖动；
- 接近可信边界时快速下降；
- small / large 使用同一归一化曲线，仅可信空间尺度不同；
- 除可信半径外没有 `w_low`、`w_high`、score floor 或衰减指数。

linear margin 和 cosine margin 只作为曲线稳健性 ablation，不作为 baseline：

```text
binary:  1[d < tau]
linear:  max(0, 1 - d / tau)
cosine:  0.5 * (1 + cos(pi * d / tau)), d < tau
```

## 7. 空间 Mask 与实例价值解耦

对每个 GT 单独生成不含质量幅值的空间 Gaussian `G_i,l(x)`。空间 mask 回答“在哪里蒸馏”，teacher value 回答“蒸馏多少”。

每个 feature level 内，将实例空间 mask 归一化为单位质量：

```text
G_bar_i,l(x) = G_i,l(x) / max(sum_x G_i,l(x), eps)
```

可等价地构造累加 mask：

```text
M_l(x) = sum_i q_i * G_bar_i,l(x)
```

重叠区域使用求和，不使用 union-max。重叠位置同时属于多个实例目标时，应保留多份实例贡献。

baseline 第一阶段保持现有 J4 的 Gaussian 几何和 AdaptiveGTScaler 能力，以控制变量；但 scaler 只能决定空间区域，不再定义 High / Medium 质量，也不能修改 `q_i`。后续应单独消融 GT-centered mask、proposal-offset expansion 和 continuous geometry adaptation。

## 8. Per-GT Feature Distillation Loss

特征误差为：

```text
error_l(x) = mean_channel((teacher_l(x) - student_l(x))^2)
```

每个 GT 内部按自己的空间 mask 面积归一化：

```text
E_i,l = sum_x(G_i,l(x) * error_l(x))
        / max(sum_x G_i,l(x), eps)
```

然后使用 teacher value 决定绝对贡献：

```text
L_l = sum_i(q_i * E_i,l) / max(N_gt, 1)
```

两级 loss：

```text
L_feature_raw = L_level0 + L_level1
L_feature = feature_weight * L_feature_raw
```

分母必须是固定有效 GT 数，而不是 `sum(q_i)` 或 `sum(mask)`：

- 除以 `sum(q_i)` 会重新抵消实例绝对价值；
- 除以 union mask mass 会让大目标和重叠关系隐式改变权重；
- `q=0.4` 应真实产生约 40% 的实例 feature gradient。

不要求构造 `[B, N_gt, H, W]` 完整 tensor。可以逐实例绘制局部窗口、计算 `E_i,l`、累加 `q_i * E_i,l` 后立即释放临时 mask。

## 9. Unmatched、跨类和未使用 Predictions

baseline 规定：

```text
unmatched GT: q = 0
same-task but wrong-class prediction: 不建立候选边
对应类别组可信半径外的 prediction: 不参与正向 ROI feature distillation
one-to-one 冲突后未分配 prediction: 不参与正向 ROI feature distillation
```

这不影响 student 的 GT detection loss 和 depth supervision，只表示 teacher 没有通过 proposal 证明自己掌握了该实例。

unmatched GT coverage prior、teacher FP knowledge 和 same-task fallback 都是独立研究问题，不能混入当前 baseline。由于 official-range 内 teacher coverage 已经很高，第一版无需为少量 unmatched 引入额外权重。

## 10. 与当前 J4 实现的差距

当前 `j4_wl05_wh07` 对应实现仍然是：

```text
same-task-group
+ class-specific High / Medium thresholds
+ each-GT highest-score selection
+ no one-to-one
+ union-max Gaussian mask
+ sum(error * mask) / sum(mask)
```

因此当前 J4 是对照 baseline，不是本文新 baseline 已落地的实现。

还需要统一 teacher checkpoint 口径：

- J4 YAML 默认指向 `ckpts/centerpoint_vox01_128x128_20e_10sweeps.pth`；
- 2026-08-21 train/val 统计使用 `outputs/train_teacher_centerpoint/checkpoints/step_step=50200.ckpt`；
- 两者不是同一文件，实验必须明确 teacher，并分别统计 one-to-one coverage。

## 11. 建议 YAML 语义

```yaml
matching:
  type: scale_conditioned_center_distance
  class_policy: exact_class
  selection: score_first_nearest_unmatched_gt
  one_to_one: true
  strict_less_than: true
  trust_radius:
    small: 1.0
    large: 2.0
  small_classes:
    - barrier
    - motorcycle
    - bicycle
    - pedestrian
    - traffic_cone
  large_classes:
    - car
    - truck
    - construction_vehicle
    - bus
    - trailer

region:
  value:
    type: normalized_squared_margin
    use_teacher_score: false
    unmatched_value: 0.0
  mask:
    normalize_per_instance: true
    overlap_merge: sum

loss:
  feature_roi_reduction: per_gt_fixed_count
  feature_weight: 0.6  # reducer 改变后必须重新校准
```

## 12. 必须重新统计的匹配指标

当前 `<1m / <2m` 覆盖率来自“每个 GT 寻找最近 exact-class proposal”，不是 one-to-one 后的真实覆盖率。新 matcher 实施后必须重新统计：

- 每类和 small / large 的 GT 总数；
- candidate degree 为 0、1、`>1` 的 GT 数；
- 同一个 prediction 在旧 matcher 中连接多个 GT 的数量；
- one-to-one 冲突消解次数；
- 冲突后 GT 仍由第二候选匹配的数量；
- 冲突后变为 unmatched 的数量；
- small `<1m`、large `<2m` 的最终 one-to-one coverage；
- 匹配距离和 normalized distance 分布；
- selected prediction 是否为该 GT 最近 proposal；
- teacher score 分布，但不将其混入 baseline value。

## 13. 必须记录的 Value 与 Loss 指标

- `q_i` 的均值、分位数和直方图；
- small / large 的平均 value；
- 每个 batch 的 GT 数、matched 数和 `sum(q_i)`；
- 两个 feature level 的 raw loss；
- small / large feature loss；
- normalized distance 分段的 feature loss；
- `q=0` 实例的 feature gradient 检查；
- feature loss 相对 detection / depth / response loss 的梯度量级。

## 14. 核心消融

### 14.1 Trust radius

| 设置 | small | large |
| --- | ---: | ---: |
| unified 1m | 1m | 1m |
| unified 2m | 2m | 2m |
| scale-conditioned baseline | 1m | 2m |

该消融回答 small / large 是否需要不同的知识可信尺度。

### 14.2 Matching

```text
旧 GT-centric matcher
exact-class GT-nearest matcher
exact-class official-style one-to-one matcher（baseline）
```

### 14.3 Value curve

```text
binary gate
linear margin
normalized squared margin（baseline）
cosine margin
```

如果多条无调参单调曲线都优于 binary gate，且结果接近，可证明收益来自连续 teacher value，而不是特定曲线调参。

### 14.4 Reduction

```text
union-max / mask.sum()（旧实现）
per-GT / sum(q_i)
per-GT / N_gt（baseline）
```

该消融验证绝对 teacher value 是否真正进入 feature gradient。

## 15. 验收标准

### 15.1 Matching

- exact-class-only；
- small 严格使用 `distance < 1m`；
- large 严格使用 `distance < 2m`；
- 每个 GT 最多匹配一个 prediction；
- 每个 prediction 最多匹配一个 GT；
- score 降序和最近未占用 GT 的结果可复现；
- one-to-one 后的真实 coverage 有完整统计。

### 15.2 Value 与 loss

- `d=0` 时 `q=1`；
- `d=tau` 及以上时 `q=0`；
- 相同 `d/tau` 的 small / large 产生相同 `q`；
- `q=0` 的 GT 不产生 feature gradient；
- 单 GT 场景下 `q=0.4` 的 feature gradient 约为 `q=1` 的 40%；
- 相同局部误差、相同 `q` 的不同大小 GT，不因 Gaussian 面积不同而产生数量级差异；
- 空 GT batch 返回图连接的零 feature loss；
- AMP 和 DDP 下无 NaN / Inf。

### 15.3 指标

- 报告每类 AP@0.5 / 1 / 2 / 4、mAP、NDS 和全部 TP metrics；
- 单独汇总 small / large；
- 重点检查 strict AP 和 mATE，而不是只看 AP@4；
- barrier 单独分析；
- 至少与 unified 1m、unified 2m 和旧 J4 matcher 对照。

## 16. 当前待决问题

1. barrier 是否应拆成 elongated group；
2. one-to-one 后 small coverage 会下降多少；
3. score-first 与 GT-nearest 哪个更适合 teacher value estimation；
4. normalized squared margin 是否优于 linear / cosine；
5. AdaptiveGTScaler 是否应保留 proposal-driven center shift；
6. per-GT reducer 改变 raw feature loss 尺度后，`feature_weight=0.6` 是否仍合适；
7. 旧 R50 teacher 与 step 50200 teacher 是否共享相同的最佳 value 规则。

这些问题通过独立消融解决，不改变当前 baseline 定义。
